# EduAgents 三分钟现场 Demo 剧本

**人设**：备考高数的自学者 **小林**。
**主线一句话**：他问的、他错的、他忘的，系统全都记着，并且每一步都能点开看证据。
**总时长**：3:00（正片 2:50 + 收尾 10 秒），**留 20 秒机动**。

> ### ⚠ 三条会前必读的真实约束（不解决就会当场翻车）
>
> **C1 · `make seed` 会生产一组真实链路历史作答。** `scripts/seed_demo.py` 会调用正式判分链路写入 2 对 1 错的演示卷，连带产生错题、BKT 和掌握度流水；重复执行会按演示卷标题幂等跳过。因此首次登录时「复习」和「我的画像」已有基线数据，第 3 步现场作答是在该基线上继续累积。
>
> **C2 · 学生与管理员演示账号已分离。** `demo@eduagents.cn` 每次 seed 都会校正为 `student`，保留全部学习语料和历史；`admin@eduagents.cn` 会校正为 `admin`，只用于运营/评估页面，不重复摄取学生语料。
> → 本剧本的设计对策：**第 4 步用终端 `make time-travel DAYS=3` 推进虚拟时钟**（`scripts/time_travel.py` 直连 Redis 累加偏移，与 API 同一个偏移键），不依赖运营页。
> → 若要在界面上操作 time-travel，请另开无痕窗口登录管理员账号；不要把学生账号临时提权，否则学生导航和演示状态会漂移。
>
> **C3 · `GATEWAY_MODE=stub` 下出题会失败、回答是开发桩横幅。** stub 模式产出的是「【开发桩响应 · 非真实模型输出】」文本，出题子图拿不到合法 JSON（`scripts/smoke_golden_path.py` 在 stub 下会显式 SKIP 掉 quiz 全链路）。
> → **必须用 `replay`（已录制 109 个 cassette，见 `cassettes/`）或 `live`**。replay 更稳，断网也能跑，界面上会有「离线回放」标注，这是诚实的工程能力展示而非造假。

## 3. 三层兜底

### L1 · Live（首选，`GATEWAY_MODE=live`）
真实 DeepSeek / SiliconFlow 调用。**风险**：现场网络、上游限流、首 token 延迟不可控。
**熔断条件**：任一步骤触发超时预案后仍失败，或连续两步超时 → 立刻切 L2。

### L2 · Replay（断网兜底，`GATEWAY_MODE=replay`）
**这是本项目的工程能力展示，不是应急丑事，要大方讲出来。**

- **切换动作**：改 `.env` 的 `GATEWAY_MODE=replay` → 重启 API（`make api`）。**会前必须预先演练一次这个切换，掐表控制在 20 秒内。**
- **前置**：`cassettes/` 已有 109 个录制目录（按请求哈希回放，含流式节奏模拟）。**演示当天使用的每一句提问、每一次出题参数，都必须是已录制过的**——临场改问题会 miss cassette。
- **界面表现**：UI 不隐藏该模式，会诚实标注「离线回放」角标。
- **配套口播（照读）**：
  > "现场网络不太稳，我直接切到我们的回放模式——这是我们模型网关的四种模式之一。请注意界面上这个『离线回放』角标，我们**不隐藏**它。这套机制不是为了应付演示：`record` 让我们的评测结果可复现，`replay` 让 CI 零 API 成本跑完 188 个单测，也让今天这个演示在断网条件下照常进行。**这本身就是一项工程能力。**"
- **L2 下仍然完全真实的部分（要讲出来）**：Qdrant 混合检索、RRF 融合、rerank 排序、分块与引用溯源、BKT 计算、FSRS 调度、虚拟时钟、RLS 租户隔离、全部数据库读写。**被回放的只有 LLM 与 embedding 的响应。**

### L3 · 备份视频（最后手段）

## 6. 个性化演示段（personalization-p1/p2 之后新增，可替换第 5 步或作加时段）

> 主线一句话升级："系统不只记着他错过什么，还知道**为什么给他这道题**——每个个性化决定都能点开看理由。"
> 叙事定位（答辩口径，来源 docs/research/brief-5-个性化.md）：**负责任的混合个性化**——认知状态由可解释的
> BKT/FSRS/KC 掌管，LLM 只负责把它翻译成有温度、可争辩的体验；我们**不做**已被证伪的"学习风格"匹配。

### 会前准备（在 §0 清单之外追加）

| # | 检查项 | 动作 |
|---|---|---|
| P.1 | 演示账号有偏好 | 「设置」页填：类比优先 / 简洁 / 兴趣"篮球、科幻" / 目标"高数期末冲 90" |
| P.2 | 有记忆条目 | 会前跑一轮辅导并答错（tutor 小结的误解会进「AI 记住的你」）；或对话 5 轮以上触发 Reflection |
| P.3 | 新会话开场卡可见 | /chat 新建对话，确认首屏出现"为你找了几件现在就能做的事" |

### 演示时刻（按冲击力排序，共约 60-80 秒，时间不够砍后面的）

1. **开场卡（15s）**：新建对话 → 首屏卡片"3 道错题到期了 / 练一练薄弱点『泰勒公式』"。
   口播："他一打开对话，系统就主动提起上次的卡点——这不是模板话术，每一条都来自他真实的
   FSRS 到期队列和掌握度记录，理由写在卡片上。"
2. **为什么这套题（20s）**：练习页点「针对我的薄弱点出题」→ 蓝图确认卡上方逐 KC 理由
   （"掌握度较弱，低于最近发展区，先用简单题打稳地基；近 7 天答错过，优先安排"）。
   口播："难度配比不是模型即兴的——后端按 BKT 掌握度算出来、程序性强制执行，蓝图模型想改也改不动；
   但**用户手改的难度我们不改回**，控制权在人。这套分档规则和我们仿真实验里跑赢随机策略三倍效率的
   那套是同一份代码，有跨包测试锁死。"
3. **可争辩画像（20s）**：画像页指着 23% →"如果他不服呢？"→ 点「验证一下」→ 3 题定向卷 →
   提交后回画像页刷新，掌握度变化 + 审计日志新行。
   口播："别的产品给你一个分数，我们允许你**反驳**它——验证卷的每道题都真实写回 BKT，
   变化有审计日志。旁边这个『我已掌握』是直接标记，我们把'验证'和'自报'诚实地分开。"
4. **AI 记住的你（15s）**：画像页底部记忆条目——"上次辅导他把洛必达用在了不满足条件的极限上，
   系统记住的是**他自己的原话**，他可以逐条删除。"（隐私口径：出境第三方 LLM 的画像只有定性词，
   掌握度小数、题干原文一律不出境，这条有测试锁死。）
5. **（加时）兴趣情境化**：设置页把兴趣改成"篮球"→ 同一知识点出题，应用题背景变成投篮命中率。
   口播："这是 Khanmigo 验证过的机制——兴趣只包装情境，知识点和难度由 BKT 定，两层各管各的。"

### 预答（个性化相关追问）

- **"个性化怎么不是套壳 prompt？"** —— 画像是 BKT/FSRS 的确定性状态，prompt 只消费定性摘要；
  难度强制、拓扑约束、重估链路全是程序硬校验，模型说了不算。测试：test_thresholds_sync（仿真-生产
  同源）、test_verify_reassess_flow（重估真实写 BKT）。
- **"为什么没有学习风格测试？"** —— VARK 类匹配已被多轮元分析证伪（d≈0.04），我们主动不做，
  用"按掌握度和求助行为调步长/详略/示例数"这一有实证支持的脚手架替代——这本身就是评审加分点。
- **"记忆会不会泄露隐私？"** —— learner_insights 存的是用户自己的话、只进他本人的 prompt；
  RLS FORCE 隔离、PIPL 导出/注销全覆盖、用户可逐条删除；画像非空即禁答案缓存，个性化答案不会
  串到别人身上。
