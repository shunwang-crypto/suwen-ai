# 第 1 页 · 问题与定位

**标题**：AI 教育产品的真问题不是「答得对不对」，是「不知道学生学到哪了」

**核心论点一句话**：我们把"这个学生学会了吗"从黑盒直觉，变成**可验证、可审计、可实验证伪的工程量**。

**页面元素清单**
- 左半：三行痛点文字（无状态 / 无证据 / 效果不可验证），配一张"聊天皮套"示意（无需数据）。
- 右半：产品定位一句话 + 人设卡「备考高数的自学者小林」。
- 底部条：核心创新统一命名 **VLSE（Verifiable Learner State Engine，可验证学习者状态引擎）**。
  - 命名与定义出处：`docs/IMPLEMENTATION_PROMPT.md` §2；构成 = KC 受控词表 + 先修 DAG + BKT 掌握度 + FSRS 复习调度 + 多模块读写同一状态。
- 右下角小字："全部宣称的证据索引见 `STATUS.md` 与 `docs/evidence/`"。
- **本页不放任何数字。**

**口播稿（约 75 秒）**
> 各位评委好。现在市面上的 AI 学习产品，本质上都是一个聊天框加一个提示词。它有三个通病：第一，无状态——你昨天答错的题，它今天完全不记得；第二，无证据——它讲的知识点出自哪本书哪一页，说不清楚；第三，效果不可验证——没人能证明用了它比不用强。
> 我们做的 EduAgents，切入点不是把答案生成得更漂亮，而是回答一个更难的问题：**这个学生现在到底学到哪了？**
> 为此我们提出一个统一的技术主线，叫 VLSE，可验证学习者状态引擎。它把知识点体系、掌握度追踪、遗忘曲线调度这三件事，收敛成一个所有功能模块共同读写的、每一次变化都留审计日志的学习者状态。
> 接下来的九页，我会先讲这个引擎长什么样，再用真实跑出来的数据，逐条证明它不是 PPT 概念。所有数字的出处文件路径我都写在页脚了，欢迎当场核。

# 第 2 页 · VLSE 一图流（核心创新页，全场重心）

**标题**：VLSE — 五个模块，一个状态，每次变化都可下钻到证据

**核心论点一句话**：别人的模块之间靠 prompt 传话，我们的模块之间靠**一个带外键、带审计日志的学习者状态**传话。

**页面元素清单**
- **主视觉：一图流（新绘 mermaid，建议落地为 `docs/vlse.md`，当前仓库尚无此文件，见差距清单 G1）**
  - 中心：`学习者状态` 三层 —— ① KC 层（`knowledge_components` + `kc_edges` 先修 DAG）② 掌握层（`mastery_records`：BKT P(L) + confidence）③ 记忆层（FSRS Card，`fsrs_card_json`）。
  - 环绕五个消费/生产方，用箭头标注读/写：**问答（qa 子图）/ 辅导（tutor 子图）/ 出题测评（quiz 子图）/ 规划（plan 子图）/ 复习（FSRS 到期队列）**。
  - 底部一条：`mastery_log` 审计流（`old_p → new_p, evidence_type, evidence_id, weight`）。
  - 表结构出处：`docs/data-model.md` §「学习者状态引擎 VLSE」与 §「知识点体系」。
- **右下角真图（关键，把概念砸实）**：截图 `docs/evidence/m4/08-profile.png` 的「最近掌握度变化」区块局部放大，可读出三条真实记录：
  - `泰勒公式 0.30 → 0.24 练习作答`
  - `泰勒公式 0.24 → 0.23 练习作答`
  - `泰勒公式 0.23 → 0.23 练习作答 ×0.5`
  - 旁注一行红字：**「×0.5 = 主观题证据的降权系数，写死在 BKT 映射规则中（`IMPLEMENTATION_PROMPT.md` §5.6），日志里直接可见」**
- 页脚证据行：`docs/evidence/m4/08-profile.png` · `tests/integration/test_reviews_flow.py`（mastery_log 逐条 evidence_id 关联 attempt，STATUS M4-D4 ✅）· `tests/unit/test_bkt.py`（11 项）· `tests/unit/test_kc.py`（17 项）
- **禁止在本页出现**："自适应比随机好 X%"（那是第 6 页的待产出实验）。

**口播稿（约 90 秒）**
> 这是全场最重要的一页。中间这个盒子就是 VLSE，它有三层。
> 最底下是 KC 层，知识点受控词表。这一层解决一个很脏但很致命的工程问题：让大模型逐段抽知识点，它会抽出「泰勒公式」「Taylor 公式」「泰勒展开」三个碎片，掌握度追踪的外键当场就崩了。我们做的是两遍式归一化——先由强档模型为整个知识库建一份词表，再逐段做别名匹配和向量兜底合并。这条有写死的测试用例，三种表述必须收敛到同一个 kc_id，17 个单测在 `test_kc.py`。KC 之间还有一张先修 DAG，做了环检测，用于学习计划的拓扑排序和学情归因下钻。
> 中间是掌握层，逐 KC 的 BKT 贝叶斯掌握度加置信度。上面是记忆层，每个错题和每个 KC 各挂一张 FSRS 卡片，算下次该复习的时间。
> 关键在外面这一圈：问答、辅导、出题、规划、复习，**五个模块读写的是同一份状态**，不是各写各的。
> 右下角这张是真实截图，不是示意图。你能看到掌握度从 0.30 掉到 0.24 再到 0.23，每一次变化都记了是哪一次作答导致的。特别注意最后这行的「×0.5」——主观题的证据强度我们写死降权到一半，因为简答题的 LLM 评分本身有噪声。**这个降权系数是直接暴露在用户界面上的**。我们认为这才叫可验证：不是我说掌握度是 0.23，而是你能点开看它凭哪几道题算成 0.23 的。

# 第 5 页 · Agentic RAG 自省环（技术深度页）

**标题**：置信度门控的自省环 —— 高置信走快路径，低置信才付自省成本

**核心论点一句话**：自省不是无脑多转几圈，**是把"要不要自省"本身变成一个由检索置信度决定的门控**。

**页面元素清单**
- 主视觉：qa 子图的真实节点图（9 节点，可用 `graph.get_graph().draw_mermaid()` 导出，或按代码手绘）
  ```
  router ──direct──────────────────────────────────► generate
     │                                                  ▲
     └─kb─► query_plan ─► retrieve ─┬─[confident]───────┘  (快路径, 跳过 grade)
                                    └─[not confident]─► grade
                                          ├─相关≥2─► generate ─► verify_support ─► END
                                          └─<2─► rewrite ─► retrieve (retry_count 硬上限 2)
                                                    └─仍不合格─► web_fallback ─► generate
     └─全部无果────────────────────────────────────► refuse ("知识库中没有找到依据")
  ```
  - 节点出处：`packages/core/src/eduagents_core/graphs/qa_graph.py`（`add_node` 共 9 个：router / query_plan / retrieve / grade / rewrite / web_fallback / generate / verify_support / refuse）
  - `_MAX_RETRY = 2` 硬上限出处：同文件第 28 行
  - 置信度门控出处：同文件 `fast_path = confident and bool(evidences)`（约 279 行）与 `if state.get("confident") and state.get("evidences")`（约 484 行）
- 右侧「四道防幻觉闸门」竖排：
  1. 检索置信度门控（低置信才进 Grader）
  2. Grader 逐条判相关（cheap 档批量单次调用）
  3. `verify_support` 生成后二次支撑度校验
  4. **敢拒答**：检索空 + web 空 → `refuse`（`STATUS.md` M3-D5 ✅，单测 + rag e2e 双覆盖）
- 左下角小图：`docs/evidence/m4/03-chat-answer.png` 的「过程时间线（12）」与右侧 5 条引用面板局部
- 页脚证据：`tests/unit/test_qa_graph.py`（16 项）· `tests/integration/test_rag_e2e.py`（2 项）· `tests/integration/test_prompt_injection.py`（2 项，5 类注入载荷）
- **诚实标注**：TTFT / 首过程事件延迟的三档口径 `[待 M5 压测产出]`（STATUS M3-D6 ⬜，stub 口径下测无意义）

**口播稿（约 90 秒）**
> 这是问答子图的真实结构，九个节点，代码在 `qa_graph.py`。
> 大家都在做 Agentic RAG，都会加 Grader 加重写重检。但无脑自省有个代价：每一轮都多两次模型调用，延迟直接翻倍。我们的做法是**把自省变成条件付费的**——检索完先看 rerank 的置信度，如果 top 结果的分数够高，直接走快路径跳过 Grader 去生成；只有置信度不够，才付 Grader 和改写重检的成本。改写重检有硬上限，最多两轮，防止死循环。
> 生成之后还有一道 `verify_support`，二次校验每个论断是不是真被引用片段支撑住了。
> 最后一条路径我特别想强调：**refuse**。检索是空的、联网也是空的，我们不生成，直接告诉用户「知识库中没有找到依据」，并且这条路径根本不调模型。教育场景里，一个自信的错答比一句"我不知道"危险得多。**敢拒答是产品和玩具的分界线**，这条有单测也有端到端测试。
> 每一步的路由理由、每条片段的判定、重试轮次、校验结果，全部作为 trace 事件流推到前端时间线——左下角这张截图里的「过程时间线 12 条」就是一次真实问答的完整决策链。
