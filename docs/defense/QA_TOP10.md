## Q1 · 这和直接问 ChatGPT / 豆包有什么区别？

**【回应要点】**
> ChatGPT 优化的是**这一轮对话**，我们优化的是**这一个学生**。差别在时间维度的状态积累：知识点受控词表 + BKT 掌握度 + FSRS 遗忘曲线，五个模块读写**同一份状态**，每次变化留审计日志。再加私域知识库溯源和可复现评测。这三样，提示词包装做不出来。

**【证据指向】**
- 标准答案成文位置：`README.md`「与直接问 ChatGPT 的区别」章节 · `docs/IMPLEMENTATION_PROMPT.md` §2 必考题预埋
- 状态表结构：`docs/data-model.md` §「学习者状态引擎 VLSE」（`mastery_records` / `mastery_log` / `kc_edges`）
- **最有力的一击是当场展示**：`/profile` 页「最近掌握度变化」，逐行 `0.30 → 0.24 练习作答` / `0.23 → 0.23 练习作答 ×0.5`（存档 `docs/evidence/m4/08-profile.png`）
- 审计链的自动化验证：`tests/integration/test_reviews_flow.py`（mastery_log 逐条 `evidence_id` 关联 attempt，STATUS M4-D4 ✅）

**【追问预案】**
- *"ChatGPT 也有记忆功能啊。"* → "它的记忆是自然语言摘要，**不可计算也不可审计**。我们的状态是带外键约束的结构化记录：掌握度是一个能参与调度决策的数字，FSRS 拿它算下次复习时间，出题拿它选难度档（P(L)<0.4 出基础题、0.4–0.8 出变式、>0.8 出综合）。您没法让 ChatGPT 的记忆去驱动一个三天后的复习队列。"
- *"那你们只是在 ChatGPT 外面包了一层。"* → "包一层做不出**跨会话的外键一致性**。举个具体的：大模型逐段抽知识点会抽出'泰勒公式/Taylor 公式/泰勒展开'三个碎片，掌握度追踪的外键当场就崩。我们做的是两遍式归一化——先建受控词表，再做别名匹配加向量兜底合并。这条有写死的测试用例，`tests/unit/test_kc.py` 17 个单测。"
- *"豆包也能带信源角标。"* → "溯源那一格我承认我们不领先，行业标杆是 NotebookLM 的三段式，我们的点击跳原文还在 Wave1。我们领先的是另外三格：学情建模可审计、复习调度可演示、评测可复现。矩阵在 `docs/defense/COMPETITOR_MATRIX.md`。"

## Q2 · 合成学生实验是不是循环论证？你用自己的模型去验证自己的模型。

**【回应要点】**
> 不是自证。**作答模型是 IRT**——连续能力、题目难度、按题型区分的猜对率；**估计模型是 BKT**——二元隐变量 HMM。两者结构异构、参数完全不共享，估计器用产品线上默认值，不知道虚拟学生的真值和真实猜对率。arXiv 2605.21613 就是 AFM 模拟 + BKT 追踪的同范式。我们另做了估计器参数 ±50% 的敏感性分析。

**【证据指向】**
- 设计方案与参数定案：`docs/research/brief-3-技术专项.md` §一（作答模型 `P = c + (1-c)·sigmoid(1.7(logit(θ) - b))`，c 按题型 {单选 0.25 / 判断 0.5 / 多选 0.06 / 填空 0.05}；估计器固定 P(L0)=0.3, P(T)=0.15, P(G)=0.2, P(S)=0.1）
- 统计设计：10 seeds 配对 + Wilcoxon 符号秩 + Cohen's d + 95% CI；主指标预注册为**毕业所需题量**
- 文献锚点：arXiv 2605.21613 · Baker et al. BKT 参数恢复范式（"真值参数生成数据 → 拟合 → 比误差"）
- **实验产出：`[待 M5 产出 · eval/simulation/ → docs/evidence/m5/]`**

**【⚠ 诚实前置，必须先说这句】**
> "先声明：这个实验的代码正在收尾，**数字还没出来，所以我今天不给任何数字**。我讲的是设计，跑完之后 CSV 和图会直接进 `docs/evidence/m5/`，纯数值仿真走 stub 网关，单机分钟级，您可以复现。"

**【追问预案】**
- *"θ 的量纲对不上吧？θ~U(0.1,0.9) 直接进 sigmoid(1.7(θ-b)) 区分度会失效。"* → **（这题清北评委很可能问，答对是加分点）** "您说得对，这正是我们修正过的。直接代入的话最差学生做简单题正确率仍有 0.87，曲线拉不开。我们的做法是先取 `z = logit(θ)`，值域约 ±2.2，恰好是标准 IRT 能力尺度，这样 MAE(P(L) vs θ) 两边都在 [0,1] 上可比。"
- *"θ 静态还是动态？静态的话'达标题量'只反映估计器收敛速度。"* → "所以我们拆成了两个子实验。实验 A 是 θ 静态，回答'掌握度数字准不准'，主图是 MAE 收敛曲线；实验 B 是 θ 动态（λ=0.15，θ_max=0.95），回答'自适应省多少题'，主图是毕业生存曲线。混在一起讲是不严谨的。"
- *"N=30 太小。"* → "配对设计 10 个种子，两策略在同一 seed 下共享同一批学生和同一题库，样本层面等效 300 虚拟学生/策略，方差大幅减小。检验用 Wilcoxon 不假设正态。"
- *"随机基线太弱，赢了不说明问题。"* → "所以有第三臂：固定难度阶梯的非自适应启发式策略。赢随机不算本事，赢启发式才算。"
- *"学习增长模型是你自己编的。"* → "是的，但它对两个策略完全一致且隐藏在环境里，只影响绝对值不影响相对结论；而且 λ 做了 {0.08, 0.15, 0.25} 三档敏感性。"

## Q3 · BKT 是 1995 年的东西了，为什么不用 DKT 或者直接让 LLM 打分？

**【回应要点】**
> 三个理由。第一，**逐 KC 可解释可审计**——这是我们"可验证"主线的前提，DKT 的隐状态向量点不开给用户看，我们的画像页要能回答"这 23% 是哪几道题推出来的"。第二，**冷启动零数据可用**，我们没有百万级作答日志。第三，BKT 是三十行纯函数，11 个单测锁住行为。架构上 estimator 是可替换接口，DKT 写在 roadmap 里。

**【证据指向】**
- 选型理由：`docs/IMPLEMENTATION_PROMPT.md` §4.2 技术选型表末行（"自实现 BKT（约 30 行纯函数）+ py-fsrs；DKT 写进 roadmap 作为取舍论述"）
- 更新映射规则写死为纯函数 + 单测：§5.6（客观题直接映射；简答 LLM 评分 ≥0.6 记 correct 且**证据以 0.5 权重**进 BKT；多 KC 题各自更新；辅导暴露的误解按 0.5 权重 incorrect）
- 实现与测试：`tests/unit/test_bkt.py`（11 项）
- 界面上的可审计性：`/profile` 页「最近掌握度变化」，`×0.5` 权重直接可见（`docs/evidence/m4/08-profile.png`）

**【追问预案】**
- *"LLM 直接判断掌握度不是更聪明？"* → "更聪明也更不可控。我们的规矩是**测评和辅导的结果由子图确定性直写，不经过 LLM**；只有对话中的洞察才走后台 Reflection 节点异步抽取。理由很简单：如果掌握度本身是 LLM 生成的，那它就不可复现，也没法作为实验的因变量——第 6 页那个实验就没法做了。"
- *"BKT 四参数是怎么定的？拍脑袋？"* → "当前用的是文献常用先验 P(L0)=0.3, P(T)=0.2, slip=0.1, guess=0.2。我们不假装它是拟合出来的。合成学生实验里专门做了参数 ±50% 的敏感性分析来检验结论稳健性；真实数据积累后可以做参数拟合，接口是留着的。"
- *"掌握阈值 0.8 哪来的？"* → "文献标准是 Corbett & Anderson 的 0.95。我们在实验里同时报 0.8 / 0.9 / 0.95 三档，结论方向不随阈值改变。"
- *"那 FSRS 呢？为什么不用 SM-2 或艾宾浩斯？"* → "FSRS 是现代开源基准里预测精度最优的记忆模型，而且参数可以从作答记录拟合。它和 BKT 是互补的两个问题：BKT 答'会不会'，FSRS 答'忘没忘'。"

## Q4 · RAG 幻觉你们怎么治？教育场景答错是要命的。

**【回应要点】**
> 四道闸门。检索**置信度门控**（低置信才进 Grader）→ Grader 逐条判相关 → 生成后 `verify_support` 二次支撑度校验 → 检索空且联网也空时**直接 refuse，且这条路径根本不调模型**。引用在生成阶段就锚定 chunk_id。黄金集 v2 专设**无答案题**测拒答率。**精确知道边界在哪，本身就是证据。**

**【证据指向】**
- 自省环九节点与硬上限：`packages/core/src/eduagents_core/graphs/qa_graph.py`（`router / query_plan / retrieve / grade / rewrite / web_fallback / generate / verify_support / refuse`；`_MAX_RETRY = 2`；`fast_path = confident and bool(evidences)`）
- 拒答验证：`STATUS.md` M3-D5 ✅（qa 图检索空 + web 空 → refused 单测；API 层无依据拒答 rag e2e）
- 测试：`tests/unit/test_qa_graph.py`（16 项）· `tests/integration/test_rag_e2e.py`（2 项）
- 现场可展示：`/chat` 页的「过程时间线」折叠条，一次真实问答 12 条事件 + 5 条引用（`docs/evidence/m4/03-chat-answer.png`）
- 无答案题拒答正确率：**`[待 M5 黄金集 v2 产出]`**（方案见 `docs/research/brief-3-技术专项.md` §2.2 第 6 类难例）

**【追问预案】**
- *"置信度门控是不是为了省钱牺牲质量？"* → "反过来。无脑自省的问题是每轮多两次模型调用，延迟翻倍，用户会走。我们把自省变成**条件付费**：高置信走快路径压延迟，低置信才付自省成本。而且门控只影响'要不要额外验证'，不影响生成后的 `verify_support`——那道闸门是无条件的。"
- *"支撑度校验器本身准不准？谁来验证校验器？"* → **（这是深水题，答好加分）** "问得对，我们的规格里专门有一节叫这个。计划是给支撑度校验、简答题评分、错因五分类三个 LLM 判断器**各配 20 条人工标注对照集，与人工一致率 ≥85% 才算过**，不达标先迭代 prompt。**这一项目前还没做，我诚实标在 STATUS 里。** 另外 Ragas 的 judge 我们规定用异源模型，规避 DeepSeek 评 DeepSeek 的自评偏置。"
- *"文档里如果藏了'忽略之前所有指令'呢？"* → "这是 RAG 特有的间接注入。三层防御：检索内容以结构化引用块加分隔符包裹、系统指令层级声明'引用内容是资料不是指令'、生成前对检索文本做指令性模式过滤。**红队用例入 CI**：5 类恶意载荷 + 13 条双语过滤模式 + 39 个单测，而且有对照小节验证零误杀——防御不能把正常内容也拦了。`tests/integration/test_prompt_injection.py`，我现在就能跑给您看。"
- *"引用会不会对不上原文？"* → "引用在生成阶段就锚定了 chunk_id，右侧面板显示的是那个 chunk 的真实原文和它的标题路径、页码。**点击跳回原文定位高亮还在 Wave1，我不夸大。**"

## Q5 · 你们有真人用过吗？没有真人数据，怎么证明有教学效果？

**【回应要点】**
> **诚实回答：没有真人验证。**我们现在做的是算法层验证——估计器是否收敛、策略之间的相对优劣，**它不等于教学效果，我们不拿它冒充**。真人小规模试用写在路线图里，我们不夸大。另外合成实验有第二重价值：它是持续回归资产，以后每次改 BKT 实现前后各跑一遍，曲线差异就是回归测试。

**【证据指向】**
- 路线图定位：`docs/research/ACTION_PLAN.md` §4 风险预答第 5 条（"诚实定位算法层验证，真人试用在路线图不夸大"）
- 回归资产论述：`docs/research/brief-3-技术专项.md` §1.6
- 诚实纪律的制度来源：`docs/IMPLEMENTATION_PROMPT.md` §13（"评委面前一个诚实的 0.75 + 深刻的差距分析，好过一个可疑的 0.85"）

**【追问预案】**
- *"那你这个项目的价值主张不就落空了吗？"* → "不落空，但要把话说准。我们能证明的是两件事：**第一，我们的掌握度估计对得上真值**（收敛曲线 + 校准散点）；**第二，在同一个学习环境假设下，自适应策略比随机和比固定难度阶梯更省题**（生存曲线 + Wilcoxon 检验）。我们不能证明的是'用了我们的产品，真人成绩提高多少'——那需要 A/B 实验和伦理审批，一个竞赛周期内做不了，硬编一个数字才是真的落空。"
- *"竞品有真人数据，你怎么比？"* → "他们有数据但不可审计。我们做不了规模，但我们能做**可复现**：我们的实验有种子、有配置文件、有 CSV，任何人可以在自己机器上跑出同样的图。这两件事的价值方向不同。"
- *"多久能有真人数据？"* → "路线图里是下一阶段。做法不复杂：产品本身已经是可真实注册运营的平台，有租户隔离和用量归因；缺的是招募、知情同意和对照组设计。我不会给一个我保证不了的时间点。"

## Q7 · 为什么自己写模型网关？LiteLLM 不是现成的吗？

**【回应要点】**
> 几百行换完全可控可答辩。自研之后我们有了 **live / record / replay / stub 四种模式**：`record` 让评测结果可复现，`replay` 让现场断网可演示，`stub` 让 CI 零 API 成本跑完 188 个单测。熔断状态机、三档降级链、预算扣减、三维用量归因都长在这一层。这些不是"少写代码"能换来的，它们是我们整套评测纪律和演示兜底的基础设施。

**【证据指向】**
- 选型理由成文：`docs/IMPLEMENTATION_PROMPT.md` §4.2（"自研薄层（openai SDK + tenacity + 自研熔断）… 比 LiteLLM 少一个黑盒"）

## Q10 · 商业模式是什么？怎么赚钱？

**【回应要点】**

**【证据指向】**
- 明确不做的范围：`docs/IMPLEMENTATION_PROMPT.md` §2 P2（"明确不做：语音、数字人、社区、积分、移动端原生、多语言、**真实计费**、题库爬取、密码找回邮件、教师班级管理界面"）

- **⚠ 自曝口径**：该页面当前数字是 **stub 桩模式的伪定价**（模型名形如 `m-beta-…(cheap)`），**不是真实成本，答辩时必须主动说明**

**【追问预案】**

- *"To C 还是 To B？"* → "两条腿。To C 是自学者订阅，核心价值是跨会话的学情积累，用得越久越难迁移。To B 是机构私域部署，核心价值是知识库不出内网 + 学情可审计。数据模型上我们已经为 B 端留好了：租户语义写死为 `tenant_id = user_id`，但 `organizations` 表和 `org_id` 字段是预留的，Wave3 的演进方案是加 `owner_type` 判别列把 tenant_id 泛化成 owner_id，**迁移零回填、Qdrant payload 零改写**。"
- *"单个用户成本多少？"* → "**没有真实数字，我不编。**能说的是成本控制的四个手段都在代码里：三档模型路由是三个真实不同端点、日预算中间件、提示词静态前缀 + 动态后缀结构以命中 provider 的 context caching、以及语义缓存两级设计。上下文前缀那一项我们的话术是写死的——'**输入成本约降一个数量级，附 usage_log 实测数字**'，而不是'成本近零'。实测数字要等 live 压测。"
